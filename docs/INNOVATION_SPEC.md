## 2. TruthGate 2.0
Input: server-scoped source references, retrieved versions/time/content digest, typed candidate claims, rule_version. Output: immutable evidence/claim/check records, source references, reason code and review state. Rule registry for requirement acceptance IDs, test result fields (reported vs observed), dates/version, policy or team owner; deterministic comparisons only on structured comparable values; free text/AI suggestions marked UNVERIFIED_CLAIM or HUMAN_REVIEW_REQUIRED. Exact quoted excerpt optional safe scoped reference, never independent evidence by repeated URL or model vote. Source stable identity + revision/digest, source independence unknown where not proved. Distinguish missing evidence from inaccessible/error. Clock/time zone explicit; freshness deadline and permission check, no silent substitution. Provider no-model fallback mandatory, external synthetic-only opt-in and quota. No raw secrets or model instructions in trusted policy. 
Caller flow: resolver preview → scoped Jira adapter → normalize → version/freshness → claims/checks → frozen bundle → typed LA planner. If missing/contradictory critical claims, REVIEW/DENY; no certified truth claim. SWU 02/03/04/06/07/08/17, CG-03/04/14.

## 3. SovereignGuard 2.0
Input: validated IR, actual server actor/installation context, target, op allowlist, current policy version/scopes, frozen dependency digest, approval nonce/expiry. Preview returns ALLOW_PREVIEW/REVIEW/DENY and exact side effects. Only approval stored server-side may authorize execution; client or AI cannot grant scopes. Approval covers one immutable plan/evidence/dependency snapshot and actor/target/policy/capability/expiry. Check current effective permission, source/policy version, scope, graph validity and target again at actual executor. On changed critical source, policy, revoked access, unknown graph, changed target, expired/consumed approval: HOLD/REVIEW/DENY; require new approval even if decision text remains same. No direct unguarded writer. 
Reserve unique attempt in supported storage (conditional transaction feasibility verified), persist attempt and expected payload digest, then call only allowlisted exact Jira operation. Use authenticated permitted actor and bounded input. After call, reread actual effect. Crash/timeout/ambiguous or conflicting result -> UNKNOWN_OUTCOME_REVIEW; no blind replay or assumed rollback. Do not claim exactly-once across Forge+Jira; preflight/readback reduce but cannot eliminate remote TOCTOU; unsupported atomic preconditions block. Bounded retry only for read or definitively unexecuted safe operations per registry. LA retains historical partial success and human compensation note.
SWU 05/09/10/11/12/13/15/23/25; CG-05/06/07/08/09/12/13/22.

## 4. ProofGraph — dynamic evidence lineage and selective revalidation
DataPassport remains complete source→claim→check→plan/policy→approval→step→actual effect→readback/receipt. Store immutable historical versioned nodes and directed dependency edges (dependency→dependent); tenant-scoped current projection, reverse index keyed by stable source/policy identity; no cross-install graph or raw originals. Dependency DAG distinct from historical audit links. 
Algorithm: (1) read authoritative source/policy revision/access in scoped adapter, compare current snapshot; (2) identify changed dependency keys; (3) bounded BFS/DFS on reverse dependency adjacency, visited set; include transitive dependents; reject cycles, orphan/unknown index, overflow, inaccessible critical source; (4) persist projection revision and affected stale/unknown statuses with reasons; invalidate corresponding approvals atomically with supported storage or conservative HOLD on conflict; preserve immutable history and unaffected projection; (5) revalidate affected checks in dependency/topological order and re-read necessary upstream inputs, re-use unaffected only if freshness/access verified; (6) freeze new immutable snapshot, draft plan if critical dependency changed, require explicit human reapproval; (7) final writer gate re-reads critical authoritative dependencies and rejects stale or unknown. Unrelated changes do not invalidate a plan whose full dependency closure and authorization remain current. Version changed but digest equal is still version change for approval binding. Revalidation result same does not revive revoked/consumed approval.
Complexity bounded by affected vertices + edges; cap and timeout conservative fail closed. Event-driven refresh optional after approval/eligibility and core; events advisory, deduped, out-of-order/missing delivery safe because mandatory prewrite re-read. No claim of all-system dependency capture; incomplete graph conservative full validation or HOLD. Do not mutate old receipts or claim tamper-proof.
SWU 14/16 lineage + 24 invalidation + 25 selective revalidation/interlock + 18 UI; CG-10/18/21/22. Required actual connected paths; graph mock is not completion.
